# Codebase review, 2026-11-07

Scope: the whole repository, with a specific brief to check that the literature
baselines on the leaderboard are real papers, correctly cited, and implemented
as described. Every arXiv ID below was resolved against arxiv.org today; the
algorithm details were checked against the papers' full text. Nothing in the
repository was modified by this review.

## 1. Verdict in brief

- **Two of the eleven "literature baselines" cite papers that do not exist in
  the stated form.** The BAE entry points at arXiv:2401.15072, which is a
  differential-geometry paper. The BIQAE entry points at arXiv:2401.14972, which
  is an HCI interview study. Both author lists are wrong. A third reference
  (Wie 2019, arXiv:1907.09965, in the architecture plan) resolves to a Harrow
  and Wei paper on quantum simulated annealing.
- **Four of the six adaptive baselines are not the papers' algorithms.** The
  FAE, BAE and BIQAE submissions are IQAE-style interval bisections with
  invented constants, and the IQAE submissions use shot counts, divisors and
  stop rules that differ from Grinko et al. The README sentence "Literature
  baselines are run exactly as specified in their papers" is true only for the
  two Suzuki MLAE entries and the two mlqae entries.
- **The published table numbers for the six adaptive baselines do not come from
  the files that were "certified".** They come from separate Numba kernels in
  `leaderboard/populate_baselines.py` that implement different algorithms with
  different parameters. Running the submission files through the harness gives
  C95 values 1.5x to 2.7x lower than the table.
- **The leaderboard "csAE" row is not csAE.** Its ESPRIT step never influences
  the final estimate; the reported 3.74 is exact maximum likelihood on the csAE
  power-of-two schedule.
- **The blind-seed anti-cheat is broken.** The certification seed is passed to
  the submission's own process on the command line, the trial table is
  reconstructible from it with a public function, and the AST scanner is
  bypassed by string concatenation. A scanner-clean demo submission certified
  at C95 = 0.000.
- **The mlqae package, its paper, its bibliography and its tests are in good
  shape.** All 19 bibliography entries check out, 13/13 tests pass, and the
  paper numbers match the pickles to the digit.

## 3. Does each baseline implement the cited algorithm?

Legend: paper = what the cited paper specifies; sub = `leaderboard/submissions/<slug>/submission.py`; kernel = the Numba implementation in `leaderboard/populate_baselines.py` that produced the published numbers.

### MLAE-LIS and MLAE-EIS (Suzuki et al. 2020): faithful
Paper: m_k = k, or m_0 = 0 and m_k = 2^(k-1); N_shot = 100; exact ML. Sub and
kernel match this. The only benchmark adaptation is the error being measured in
a = sin(theta) rather than sin^2(theta). Harness runs reproduce the published
numbers bit for bit.

### mlqae-plain and mlqae-flagship: faithful
Same code as `mlqae/core.py`. Two notes: the submission calls
`ml_estimate_batch` without `eta`, so on any noisy track it is the
noise-ignorant estimator, unlike the in-schema `MLQAEFlagshipSubmission`
(`schema_and_api.py:867`). The flagship ladder stops at 803 for n_max = 1000,
so the submission uses only 80% of the permitted depth.

### IQAE-CP and IQAE-Chernoff (Grinko et al. 2021): structure right, parameters wrong
Paper: N_shots = 100; late-stage shot reduction divides by 10; T = ceil(log2(pi/(8 eps))); r = 2; no query cap, no round cap; final estimate is the midpoint.
- sub uses 28 and 32 shots, divides by 8 (`iqae_grinko:151`, `iqae_chernoff_grinko:160`), T = ceil(log(1/(2 eps))/log r), adds `hard_query_limit = 25 n_max`, `max_rounds = 48/52`, an early exit at the depth cap, and (Chernoff variant only) a 49-point likelihood polish inside the interval that is not in the paper (`iqae_chernoff_grinko:88-109`).
- kernel uses 100 shots and divides by 10 but targets eps95 read from `mlqae/head_to_head.pkl` rather than a fixed constant (`populate_baselines.py:827-855`), and uses a normal approximation to Clopper-Pearson beyond 700 flips.
- The epsilon targets (0.22/n_max, 0.24/n_max) are tuning choices, not paper values.

### chebAE (Rall and Fuller 2023): published numbers come from the authors' code; the submission is a loose port
The published row is copied from `mlqae/head_to_head.pkl` (`populate_baselines.py:916-935`), which ran the root `chebAE.py` (the qiskit-community reference code, Nshots = 100, nu = 8, r = 2) at **2,000 trials, not 20,000**, with **no depth cap** (47% of trials at n_max = 125 exceeded the cap), and `num_rounds_mean = 15.0` is hard-coded at line 931. The submission uses 36 shots instead of 100, eps = 0.21/n_max, and `max_steps = 220`. The sentence "11/11 certified" does not cover these numbers.

### FAE (Nakaji 2020): not the paper's algorithm
Paper: stage 1 inverts cos(2(2m+1) theta) with Chernoff bounds at depths 2^(j-1); switches to stage 2 when 2^(j+1) theta_max >= 3 pi / 8; stage 2 measures depths 2^(j-1) and 2^(j-1) + 2^(j0-1) and combines them with the cosine addition formula (Eq. 14-16) and atan unwrapping; N_1st = 1944 ln(2/delta_c), N_2nd = 972 ln(2/delta_c); no likelihood anywhere; no early stop.
- sub uses Clopper-Pearson intervals (metadata says "Chernoff"), 22 and 8 shots, an auxiliary depth k + k_prev/2 (not k + 2^(j0-1)), and replaces the trigonometric solve with a 97-point grid log-likelihood plus an ad hoc penalty `-2 (diff_grid - diff_obs)^2` (`fae_nakaji:67-108`). The final estimate is a grid MAP over all records.
- kernel is a different approximation again (Hoeffding intervals, 40/30 shots, weighted average of two candidates). Harness run of sub gives C95 = 3.19 vs the table's 8.79.
Neither implementation reproduces Nakaji; the real algorithm with the paper's shot counts would be far more expensive than either.

### BAE-Adaptive (Ramôa and Santos 2025): not the paper's algorithm
Paper: sequential Monte Carlo posterior with MCMC moves; the next Grover count is chosen by greedy one-step look-ahead on expected posterior variance, with an adaptive window-expansion search range; estimator is the posterior mean; nothing proportional to 1/sigma, no credible-interval branch restriction.
- sub is an IQAE-style interval bisection with Beta(1+k, 1+n-k) credible intervals at alpha = 0.003, a degree rule max(branch-limited, round(0.55/sigma)) with step ratio 1.65, shot tiers 12/8/4, and a final estimate 0.5 (posterior mean + MAP) on a 73-point grid (`bae_ramoa_santos:102-127, 163-222`). None of 0.55, 1.65, 5.92, 0.003, 0.19 appear in the paper.
- kernel is a 4096-point grid posterior with a depth rule round(0.5 (1.15/sigma - 1)), random +-1 jitter, and 3 shots per step (`populate_baselines.py:467-582`). Also a different track (fixed-budget vs variable).
The two are different algorithms from each other and from the paper. The table's 3.03 is the kernel; the sub gives about 2.9 at n_max = 125.

### BIQAE (Li et al. 2025): not the paper's algorithm, and not a literature baseline at all in its current form
Paper: Beta posterior credible intervals replace Clopper-Pearson; posterior accumulates within a stage and is pushed through sin^2(K f(p)) and refit when k changes; k chosen by linear search as in IQAE; final estimate is the interval centre; N_incre = 10, alpha = 0.05.
- sub: Jeffreys Beta(0.5+k, 0.5+n-k), fixed alpha = 0.0035, 14 shots dropping to 4, final 65-point grid MAP (`biqae_bayesian:21-29, 116-118, 175`).
- kernel: Beta(k+1, n-k+1), alpha = 0.015/T, 36 shots, posterior-mean readout (`populate_baselines.py:177-188, 898-907`).
The README reference column says only "Bayesian Beta-IQAE" with no link, and `populate_baselines.py` lists the author as "BIQAE Reference Baseline". Harness run of sub gives C95 = 3.34 vs the table's 4.65.

### csAE (Labib et al. 2024): the leaderboard row is a different estimator with the same name
`leaderboard/submissions/csae_esprit_labib/submission.py` reproduces the csAE power-of-two schedule and shot ramp (identical to `csae/signals.py` for power-of-two n_max), but:
- `progressive_dyadic_sign_candidates` (lines 121-149) is a global NLL grid search at basin/6 resolution, i.e. the same construction as mlqae's exact ML, and its optimum, polished by `disambiguate_quadrant_and_refine` (lines 78-118), seeds the answer (line 191).
- The ESPRIT candidates can only replace that seed if their refined NLL is lower, and they are refined by the same routine. A paired run on identical counts gives p95 error 8.14e-3 with and without the ESPRIT loop (identical to three digits), versus 1.24e-2 for the real `csae/` package and 2.31e-2 for ESPRIT alone with true signs.
- `build_virtual_ula_and_esprit` caps the ULA at 32 and the Toeplitz matrix at 16x16 (lines 48, 58), so it only ever uses physical depths {0, 1, 2, 4, 8} regardless of scale. There is no 2q-th order coarray, no learned sign table, no sliding-window sign search.
The published 3.74 is therefore "exact ML on csAE's schedule", which `mlqae/paper/main.tex:61` already describes as a ~10% improvement over csAE's 4.3. It should not be presented as a reproduction of the paper.

## 4. Provenance of the published numbers

## 5. Harness and anti-cheat (`leaderboard/`)

Ranked. Items 1-3 were verified by writing demo submissions in the scratchpad (not the repo).

1. **Critical: the blind seed is handed to the submission.** `.github/workflows/leaderboard_ci.yml:646-652` runs `verifier_and_runner.py --mode=certify --seed="$BLIND_TEST_SEED" --salted-seed=...` in the same process that imports the submission. `--seed` becomes `seed_band` (`verifier_and_runner.py:1591, 1643`), and the trial table is `generate_trials(ntrials, seed_band + nmax)` (`1281`, `harness.py:33-39`), a public deterministic function. The per-trial RNG handed to `run_trial` is `default_rng(t_seed ^ ALG_RNG_XOR)` (`602`), so its first draw identifies the trial. A submission that reads `sys.argv` via `import sys as s` (the scanner only matches the literal name `sys`, lines 376-379), rebuilds the tables, and otherwise falls back to an honest estimator passed all five stages and certified at C95_ave = 0.000 at every scale. The `--salted-seed` concordance check falls the same way. The in-process HMAC path (`derive_blind_seed_and_permutation`, 147-164) is never used in CI because the raw secret is unset before launch.
2. **Critical: the AST scanner is string-literal based and trivially bypassed.** All of the following pass with zero violations: `operator.attrgetter('_'+'getframe')(s)(1)`, `attrgetter('__getattr'+'ibute__')(object)(oracle, '_dispatch')` (reaches the GuardedOracle closure and hence `secret_theta` and `meas_rng`), `import __main__; __main__._STARTUP_SECRET_SEED`, `import numpy as nmp; nmp.load(...)`, `pathlib.Path(...).read_text()`, `import os as o_; o_.environ`, and `sys.path.insert(...)` followed by importing an unscanned helper module (only `submission.py` is scanned, lines 444-447). The honeypot frame (869-872) also exposes `zero_info_mode`, so a cheater can behave honestly exactly when the zero-information test is running. The `tamper_attempts` check (885) is dead code because `GuardedOracle.__getattribute__` raises before dispatch (563-567).
3. **High: stages 4 and 5 run only on the public SEARCH_SEED band** (`1037-1044`, `1625-1631`), so seed-keyed cheating in the certification band is invisible. Thresholds are lenient: returning a_true on 30% of trials and garbage otherwise passes stage 4 with probability 0.94. Stage 5 accepts 1/sqrt(N) scaling (`eps2 < 0.70 eps1`), so it is not a Heisenberg check as the README says.
4. **Medium: measurement RNG derivable from algorithm RNG in principle.** `t_seed` is 31-bit and both generators are seeded from it (`601-602`); `rng.bit_generator.state` is not blocked. Impractical today under the CPU limit, but the fix is to draw independent seeds as `schema_and_api.evaluate_adaptive_submission` already does (`1150-1151`).
5. **Medium: the headline C95 "95% CI" is not a confidence interval.** `entry_builder.py:139-150` averages the four per-scale lower bounds and the four upper bounds; for four independent scales this is about 2x too wide. Conservative but mislabelled in the README table.
6. **Medium: sequential-depth accounting differs between the two oracles.** The CI oracle charges a depth-0 round as 1 unit (`641`, `683`); `QuantumAEOracle` charges 0 (`schema_and_api.py:317, 378`). Affects C95_seq for every adaptive method that starts at depth 0. The README does not define this.
7. **Medium: no query budget is ever enforced in CI** (`_run_trials_guarded` always receives `max_queries=None`, 841 and all call sites), so the "adaptive-fixed-budget" track is declarative only. The depth cap is enforced (881, 542-543, 659).
8. **Low:** the wide-prior pass silently uses `max(500, ntrials//2)` trials and `max(200, B//2)` resamples (1270, 1292), undocumented; the CLI default is 2000 trials while CI uses 20,000.
9. `ml_estimate_batch` (`schema_and_api.py:584-656`): no bug of consequence; numerically identical to `mlqae/core.py` on 3000 records. `test_verifier.py` exits 0.

## 6. The `csae/` package itself

1. **Accuracy depends on an undocumented alias correction, not on ESPRIT with the recovered signs.** `csae/util.py:68-84` (`apply_correction`) replaces the ESPRIT angle by the likelihood-best of seven aliases {theta, pi/2 - theta, pi/4 - theta, theta/2, theta/4, ...}, inside the sign-search objective (`estimator.py:31`) and at the end (`:358`). With the recovered sign vector the raw ESPRIT angle has median amplitude error 0.22 (p95 0.81); after correction 2.6e-3; the non-identity alias was chosen in 14 of 25 trials. The paper's Algorithm 3 (`quantum journal/main_quantum.tex:336-357`) returns sin(omega/4) with no such step.
2. **The "learned sign distribution" is deterministic.** `simulate_signal` (`util.py:57-62`) uses the exact sign and only samples the magnitude, so the 1000 MC draws per grid point differ only where p_hat hits 0 or 1 (producing sign 0). Zeros survive the window search (`util.py:249` multiplies variations) and reach the final sign vector in every trial run; the "init samples s" ablation in the paper (`main_quantum.tex:708-709`) therefore only varies RNG consumption.
3. **Paper/code mismatches**: shot formula is linear in index (`signals.py:168-185`) vs logarithmic in depth in the paper (identical only for pure powers of two); depth-0 doubling is in the code and tables but not the text; paper says depth-0 calls are halved in the query count but code adds the full N_0; the Toeplitz matrix is (ULA+1)/2 square (`signals.py:122`), not ULA square as Algorithm 2 states.
4. Smaller bugs: `frequencyestimator.py:243-247` `p0mp1` is never passed so the theta ~ pi/2 branch fires on proximity alone; `estimator.py:334` references an undefined `measu` (dead path raises NameError); `signals.py:34` `if seed:` ignores seed 0; `frequencyestimator.py:206` ignores its `n` argument; `estimator.py:166-169` has an `if`/`if` where `if`/`elif` was intended; `plots.ipynb` loads `csae/sims/` while the README writes to `csae/sims_final/`.
5. README constants 4.3/eps and 0.26/eps are consistent with `plots.ipynb` (4.347 +- 0.136, 0.264 +- 0.011 from `csae/sims/`; `sims_final/` gives 4.28 / 0.26). The 99% constant differs between the two sim directories (8.99 vs 7.6).

## 7. The `mlqae/` package and paper

- `geom_ladder`, `canonical_shots`, `flagship_schedule`, and the grid ML estimator are correct; KAPPA constants re-derived to six digits. 13/13 tests pass in about 10 s (`test_mlqae.py:10` still says "~2 minutes").
- Every Table I/IV entry and the README range reproduce from `paper_numbers.pkl`.
- All 19 `refs.bib` entries are real and correctly attributed. The paper does not cite Nakaji's FAE; a referee may ask for it.
- One theoretical caveat worth a sentence in Appendix A: when the 4 sigma branch of `grid_spacing` binds (s >~ 30), the coarse grid can under-sample the true mode by up to 2 nats, so "guaranteed to straddle the mode" is a bracketing guarantee, not a global-maximum guarantee. Table VI defends it empirically.
- Housekeeping: the working title "Dense-ladder ..." persists in eight places (section 2); `README.md:84` says `final_numbers.py` runs in 55 s while the script says 13 min; `README.md:72` says the pkls are the paper snapshots but `head_to_head.pkl` was rewritten on 2026-10-23/27; `mlqae/paper/.gitignore` still excludes `main.bbl` (open item from the 2026-09-02 review).

## 8. Recommended actions, in order

1. Fix the three wrong citations and the author names everywhere they appear (submissions, metadata, `populate_baselines.py`, README, all three JSON files, architecture plan, docstrings). Replace "Quantum (2024)" for csAE with the arXiv reference. Replace "Dense-ladder ..." with the arXiv title.
2. Decide what the adaptive baseline rows are. Either (a) implement FAE, BAE and BIQAE as the papers specify (SMC for BAE; Chernoff shots and the cosine-addition stage 2 for FAE; Beta prior push-through for BIQAE) and present them with the papers' parameters, or (b) relabel them honestly as "IQAE-style interval variants inspired by X" and drop the "run exactly as specified" sentence. Either way, make one implementation the source of truth: the table should be regenerated from `leaderboard/submissions/` through the same harness used for challenge entries, with the depth cap enforced and 20,000 trials for chebAE.
3. Rename or re-describe the csAE row as "exact ML on the csAE power-of-two schedule", or make the submission call the `csae/` package.
4. Close the seed leak before accepting external submissions: run the submission in a child process that only sees an oracle RPC, never put the seed on argv or in the environment of that process, scrub `sys.argv`, draw independent oracle and algorithm seeds, and run the zero-information test in the certification band. Treat the AST scanner as defence in depth only.
5. Fix the headline CI aggregation, define C95_seq for depth-0 rounds in one place, and either enforce or remove the fixed-budget track.
6. Add the `apply_correction` step and the deterministic sign table to the csAE paper's algorithm description, or change the code to match the paper, before the Quantum submission.
